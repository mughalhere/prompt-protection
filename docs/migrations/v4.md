# Migrating to 4.0

4.0 shrinks the root entry to the stable tier and tiers the rest. No scoring, guard or rule
behaviour changes. `RULES_VERSION` is unchanged.

## Moved out of the root entry

| Was at root | Now at | Tier |
|---|---|---|
| `normalize`, `resolveAction`, `precisionAllowsBlock`, `computeSeverity`, `analyzePromptWith`, `INTERNAL_ERROR_RULE` | `prompt-protection/internal` | internal |
| `flattenChatMessages`, `isChatMessageArray`, `resolvePromptInput` | `prompt-protection/internal` | internal |
| `ALL_RULES`, `OUTPUT_RULES`, `TOOL_RULES`, per-category rule arrays, `DEFERRED_REFERENCE_RULE_IDS` | `prompt-protection/internal` | internal |
| `NormalizeResult`, `AnalyzeFn` (types) | `prompt-protection/internal` | internal |
| `mlClassifier`, `createClassifier`, `predict`, `fuseVerdict`, `ML_RULE_ID`, `Classifier*` and `ModelMeta` types | `prompt-protection/ml` | preview |
| `spotlight`, `unspotlight`, `spotlightInstruction`, `Spotlight*` types | `prompt-protection/spotlight` | preview |
| `createCanary`, `injectCanary`, `detectCanary`, `promptSimilarity`, `*CanaryOptions` types | `prompt-protection/canary` | preview |

`prompt-protection/lite` drops the same internal and spotlight/canary re-exports; it keeps
`analyzePrompt`, `verifyPrompt`, `stripPrompt`, `analyzeOutput`, `PromptInjectionError`,
`RULES_VERSION` and the types.

Mechanical fix: change the import path. Nothing was renamed.

```diff
-import { analyzePrompt, normalize, spotlight } from 'prompt-protection';
+import { analyzePrompt } from 'prompt-protection';
+import { normalize } from 'prompt-protection/internal';
+import { spotlight } from 'prompt-protection/spotlight';
```

## Open unions

`ThreatCategory`, `ProtectionEvent['type']`, `ProtectionEvent['direction']`, guard `SinkKind` and
`FlowKind` now end in `| (string & {})`. An exhaustive `switch` with a `never` default stops
compiling; replace the `never` branch with a `flag`/pass-through default. Autocomplete for the known
values is unchanged.

## Everything else

`AnalysisResult`, `OutputAnalysisResult`, `ProtectionEvent`, the guard API, the MCP server tools, the
adapters and the middlewares are unchanged. `ml` stays `'off'` by default.
